# Take over a milestone (`resume <project>`)

Use this when the coordinator session broke off, filled its context or was cleared in the middle of a milestone. The current milestone comes from SKILL.md section 2. Its state board is `STATE.md` in the milestone's output folder (`<project>-m<n>-<YYYYMMDD>/` under the registry's output folder; if there are several, the latest date).

1. **Only a coordinator resumes.** If this session is a worker (it received a brief, or its prompt carries an Orca Task and Dispatch ID), stop; a worker follows its brief.
2. **Read the state board.** If the current milestone is not Active, say so and stop: there is nothing to take over, and `start` begins a milestone. If the output folder already has `REPORT.md`, the milestone is waiting for the user's check: say so and point to `/milestone end <project> <n>`. If `STATE.md` is missing, say so and rebuild it from what exists: the Run whose objective is `<project> M<n>` in `orca orchestration run-list`, this milestone's briefs in `briefs/`, `history/m<n>.md`, and the worker branches (`<feature branch>-m<n>*`) in each related repo.
3. **Rebind the Run.** Run the `orchestration` skill to read the guide for the installed Orca version, then `orca orchestration run-use --id <Run ID>`. Pass `--environment local` on this and the commands in step 4, as the guide does for every Run command run on this machine. Start no worker before this: with no Run bound, `worker-start` creates a new Run, and the old workers' reports land in a mailbox nobody reads. If `run-use` refuses (for example, the old coordinator terminal is still alive and bound), follow the guide, and ask the user before stopping that terminal.
4. **Refresh from Orca and git.** Read `orca orchestration task-list --run <Run ID>`, `worker-list --run <Run ID>`, and the coordinator mailbox (`orca orchestration inbox --terminal run:<Run ID>`) for reports and questions that arrived while nobody was coordinating. Check which worker branches are already merged into the feature branch. Where these disagree with `STATE.md`, they win; overwrite `STATE.md`.
5. **Show the state** after the three lines: the phase; a table of workers (repo, brief, status from Orca, what you wait for); reports and questions found in step 4 that are still unanswered; findings not yet ruled on; and the next step.
6. **Carry on** from `references/start.md` step 5 under the same rules: answer the waiting questions, handle the reports, keep `STATE.md` current, and report once at the end (step 6).
